Architecture

멀티 모듈 구조

기능 단위 독립 모듈로 구성된 Clean Architecture

📦 Piece Android

├── :app // 앱 진입점, DI 루트
├── :presentation // 공통 UI, 테마
├── :feature/* // 기능 단위 독립 모듈
│ ├── :feature/onboarding
│ ├── :feature/matching
│ ├── :feature/store
│ └── :feature/...
└── :core/* // 공통 레이어
├── :core/domain
├── :core/data
├── :core/network
├── :core/datastore
├── :core/common
├── :core/common-ui
└── :core/navigation
⚖️ 의존성 방향 준수 — presentation → domain ← data 원칙 유지. feature 모듈 간 직접 참조 최소화

Tech Stack

기술 구현

확장 가능한 아키텍처를 위한 기술 선택

🎨

Jetpack Compose · MVI

Screen / State / Intent / SideEffect 패턴으로 UI 상태 관리 일관성 확보. 단방향 데이터 흐름으로 예측 가능한 화면 구현

🏗️

Clean Architecture · Multi Module

도메인 단위 모듈 분리로 변경 영향 범위 축소. 비즈니스 로직은 domain에 집중, UI/플랫폼 코드는 presentation/data로 분리

📊

Analytics · GA + Amplitude

퍼널/행동 이벤트 기반 이벤트 스키마 설계. 온보딩·매칭·전환 등 핵심 사용자 흐름 분석 구조 구축

⚙️

Build-Logic · 빌드 표준화

컨벤션 플러그인으로 빌드 규칙 통일. debug / qa / release 변형 분리 운영

✅

Ktlint · 테스트 · 아키텍처 리뷰

Ktlint 정적 분석 및 unit/androidTest 체계 운영. 리뷰 기준에 아키텍처 준수 항목 포함해 구조적 일관성 유지
